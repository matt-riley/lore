## Known limitations

- Operation-deadline expiry (504) has no stage-1 wire operation slow enough to
  exercise it end to end; the receive deadline (408) is proven over the socket,
  and the operation path is unit-tested. Stage 2 revisits once a durable
  operation exists.
- Repository resolution shells out to `git` with no explicit process timeout,
  matching v1; a hung `git` blocks resolution until the process exits.
- `MAX_TIMEOUT_MS` = 5 s is an implementation clamp, not yet a contract
  constant; stage 2 should confirm or amend it.
- The slow-body test asserts the 408 within a 3 s bound; on a heavily loaded
  runner this is the most timing-sensitive assertion in the suite.
- Windows, remote daemon access, embedded inference and ANN indexing remain
  excluded per the roadmap.

## Gate decision

G1 passes: one protocol serves the Node, Bun and Rust clients without
host-specific framing shims; the Rust CLI works without Node; and this record
identifies dependency versions and unsupported capabilities. Durable
behavior, storage and the remaining routes begin at stage 2
([02-daemon-core](../02-daemon-core.md)).
