Interface coverage:

- Implemented routes: `POST /v2/status`, `/v2/retain`, `/v2/forget`,
  `/v2/recall` (lexical only). Advertised capabilities:
  `status.basic`, `memory.retain.manual`, `memory.forget`, `recall.lexical`.
- Not implemented: embeddings/jobs (stage 3), ingestion (4), extraction and
  migration (5), adapters/administration (6), packaging/cutover (7).

Policy and durability evidence:

- Scope: global-only recall without a repository; same-repository evidence;
  foreign `repo` rows never returned; cross-repository `transferable` rows
  only with explicit consent; expiry exclusive at exactly now.
- Retries: identical payload replays the original acknowledgement; the same
  key with a different payload is `IDEMPOTENCY_CONFLICT`; keys are namespaced
  per client; a Retain replay after Forget returns the original receipt and
  does not resurrect the row.
- Forget: content cleared, fingerprint-suppression row written, FTS row
  removed, counters and revision advanced atomically; repeated Forget with a
  new key returns `alreadyForgotten` without another revision; unknown IDs
  return `MEMORY_NOT_FOUND` with no tombstone.
- Rollback: an injected failure before commit leaves no memory, receipt or
  revision change; the retry succeeds as a fresh write.
- Durability: acknowledged writes are visible to an independent SQLite
  connection, survive a closed/reopened store, and survive a SIGKILL plus
  daemon restart with the same receipt replay.
- Lifecycle: store and endpoint double ownership refused; a different store
  cannot take a live socket; a stale socket is revalidated and replaced;
  symlinked endpoints and directories containing v1 `lore.db` are refused;
  SIGTERM drains and removes only the socket this instance bound.
- Disabled config: Status reports `unavailable`/`CONFIG_DISABLED`; memory
  operations return 412 and write nothing.
- FTS safety: metacharacter and Unicode queries do not error; ties break on
  ascending ID deterministically; v1's OR-retry restores recall when the
  strict AND query finds nothing.

Lexical quality (shared curated fixture, 11 queries, 12 memories): recall@6
= 1.0, MRR@6 = 1.0, irrelevant-context rate = 0.0.

## Lexical benchmark

10,000 synthetic memories, 200 queries, four concurrent clients, release
build, Apple M5, Node 26.9.0 client over the socket.

| Metric | v2 daemon (client-observed) | v1 in-process lexical |
| --- | --- | --- |
| Recall p50 | 1.756 ms | 1.507 ms |
| Recall p95 | **2.888 ms** | 33.460 ms |
| Recall p99 | 7.578 ms | 35.916 ms |
| Retain p50 / p95 | 0.268 / 0.429 ms | not measured (direct SQL load) |
| Corpus load | 3.18 s | 0.79 s |
| Stores + WAL | 9.72 MB + 4.24 MB | n/a |
| Idle-to-loaded RSS | 23.2 MB | n/a |

Gate: p95 ≤ max(5 ms, 2 × v1 p95 = 66.9 ms) and ≤ 100 ms → **2.888 ms
passes**; foreground Retain p95 ≤ 100 ms → **0.429 ms passes**; idle RSS
≤ 100 MiB → **23.2 MB passes**. The v2 figure includes socket and HTTP
overhead while the v1 figure is in-process, so the comparison is
conservative in v1's favour.

## Known limitations

- Cancellation is proven for an already-expired deadline and by a watchdog
  that interrupts the reader connection; the corpus did not exercise a
  mid-statement interrupt on a slow query, so that path relies on a unit
  test plus the expired-deadline integration test.
- Admission is one bounded semaphore (32) with a per-client counter (8); the
  reserved request classes and writer-priority scheduling from
  `configuration-storage.md` are simplified for this stage.
- Read-pool sizes are fixed at four; no 1/2/4 sweep or flood test yet.
- Status counts read maintained columns, but receipts use `COUNT(*)`.
- Backup, restore, migration and provider work are untouched; `synchronous=FULL`
  plus SIGKILL is not power-loss certification.
- The benchmark is a local developer run; no competing workloads were run,
  but it is not a controlled CI benchmark.

## Gate decision

G2 passes: acknowledged writes survive process failure, retries and Forget
work through the real API with zero policy failures, scope fixtures show no
leaks, and lexical recall beats the measured v1 baseline within the declared
budgets on both Linux and macOS. Stage 3 (background embeddings and bounded
query inference) is next per [03-background-embeddings](../03-background-embeddings.md).
