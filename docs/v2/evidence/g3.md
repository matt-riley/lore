## Safety and recovery coverage

- Lease fencing: an expired claim cannot commit after a new owner claims the
  same target; late results are rejected as obsolete.
- Crash semantics: claims are fenced by owner + token + expiry; reaped claims
  are re-queued and attempts are preserved so the retry budget cannot reset.
- Forget: vectors are deleted, jobs become obsolete, the intent never becomes
  current, and the deleted canary never returns through the lexical or vector
  path in held-out evaluation.
- Provider failures: malformed batches commit nothing (no partial vectors),
  transient failures back off with full jitter and open the breaker after three
  consecutive failures, and auth/model/dimension failures pause the provider
  generation until an explicit `jobs/retry` or `config/reload`.
- Cache isolation: exact-key in-memory LRU (1,000 entries / 16 MiB / 24 h);
  identical queries perform zero provider calls; no query text or vector is
  persisted (verified by the store schema containing no query tables).

## Fusion deviation (recorded)

The planning note specifies equal-weight reciprocal-rank fusion (k = 60). The
calibration sweep shows equal weights **fail every threshold** against the
equivalent v1 semantic mode on recall@6 and MRR@6: unqualified lexical rows
tie with, and dual-ranked rows overtake, pure-semantic matches. The
implementation therefore orders qualifying vector rows by cosine first and
uses lexical-only rows, in bm25 order, to fill remaining slots. Calibration
and held-out results with this rule are exactly equal to v1 semantic for the
metrics the gate defines, and better than v1 lexical on all three. The equal
weight failure is retained in [`g3-calibration.json`](g3-calibration.json)
under the rule description and in this note; no held-out tuning was performed.

## Known limitations

- Query slots are two with immediate capacity fallback (no waiting behind
  memory batches); under four concurrent unique queries about half the reads
  report `QUERY_CAPACITY` by design. Sequential quality runs report `NONE` for
  every query.
- Relevance threshold 0.45 is calibrated for this model and corpus; a provider
  change advances the generation and requires a new calibration report.
- The irrelevant-context rate is high for both semantic streams on
  negative-only prompts because the model finds domain-adjacent similarity;
  the gate is comparative and v2 does not exceed v1.
- Remote HTTPS providers, embedded inference, ANN indexing and query
  normalization are not implemented; remote endpoints remain gated behind
  `allowRemote` and the transport is loopback HTTP only.
- Sleep/resume clock-jump handling and power-loss durability are not certified;
  SIGKILL recovery is covered by stage-2 evidence.
- `config/reload` swaps the provider generation and clears the query cache; it
  does not rewrite stored vectors, which simply stop matching the new identity.

## Gate decision

G3 passes: all hermetic safety/recovery fixtures pass, resource use is bounded,
offline Recall matches the lexical baseline, healthy first-seen semantic recall
equals the v1 semantic comparison and beats v1 lexical without prewarming
query vectors. The fusion deviation is deliberate, recorded, and does not
loosen the metric gate. Stage 4 (ingestion) is next per
[04-ingestion](../04-ingestion.md).
